## Generated project

`gungnir new hello` creates these application paths:

| Path | Purpose |
| --- | --- |
| `app/controllers/HomeController.gnr` | Starter controller |
| `app/models/` | Model declarations |
| `app/middleware/` | Middleware declarations |
| `routes/web.gnr` | Web route declarations |
| `views/welcome.html` | Starter view |
| `bootstrap/app.hpp` | Editable C++ configuration and boot hooks |
| `config/` | Application configuration directory |
| `database/migrations/` | Migration source |
| `.env`, `.env.example` | Local environment and example values |
| `.gungnir-project` | Project name and structured compiler profile |

Generators create additional source directories when needed, including `app/events`, `app/listeners`, `app/policies`, `app/notifications`, `app/mail`, `app/jobs`, and `app/requests`.

## File names and imports

Declaration generators preserve PascalCase names: `User.gnr`, `UserController.gnr`, and `AuthMiddleware.gnr`. Migrations use snake_case file names.

A file at `app/models/User.gnr` has module path `app.models.User`. Import it explicitly when another module needs its declarations:

```gnr
import app.models.User;
```

See [Modules](/docs/modules/) for aliases and resolution rules.

## Build output

The CLI writes generated native code and build output under `.gungnir/`. Application builds compile structured modules together, validate routes, and preserve unchanged generated files for incremental native compilation.

`bootstrap/app.hpp` remains application-owned and is never regenerated by builds. See [CLI and Code Generation](/docs/cli/) for all generators and commands.
