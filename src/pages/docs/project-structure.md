## The Root Directory

A newly created application follows this structure:

~~~text
my-app/
├── app/
│   ├── controllers/
│   ├── middleware/
│   └── models/
├── config/
├── database/
│   └── migrations/
├── routes/
│   └── web.gnr
├── views/
├── .env
├── .env.example
└── .gungnir-project
~~~

The goal is simple: application concepts should have obvious homes, and framework-generated output should stay out of those directories.

## The App Directory

The `app/` directory contains the core application code.

### Controllers

`app/controllers/` contains HTTP controllers:

~~~gungnir
controller UserController
{
    Response index()
    {
        return json(User::all());
    }
}
~~~

### Models

`app/models/` contains ORM models and their relationships:

~~~gungnir
model User
{
    string name;
    string email;
}
~~~

### Middleware

`app/middleware/` contains request middleware that can inspect, reject, or continue requests.

## The Config Directory

The `config/` directory is the conventional home for application-level configuration. Environment-specific values should come from `.env` or the process environment rather than being hard-coded into application code.

## The Database Directory

`database/migrations/` contains migration files that describe database changes over time.

Models describe how application code works with data; migrations describe how persistent storage changes.

## The Routes Directory

`routes/web.gnr` contains the application's web routes:

~~~gungnir
Route::get("/users", UserController::index);
Route::post("/users", UserController::store);
~~~

Keep route files focused on URLs, controller actions, middleware, and grouping rather than business logic.

## The Views Directory

`views/` contains server-rendered templates. By default, view names resolve underneath this directory:

~~~gungnir
return view("users/index", {
    "users": users
});
~~~

## Environment Files

`.env` contains local environment values. `.env.example` documents the keys a project expects without containing production secrets.

## Framework-Managed Files

The `.gungnir/` directory is generated by the framework build process. It may contain generated native source and build artifacts. Do not edit those files as application source; regenerate them through the Gungnir CLI instead.
